Added SOC Week 3 Practical and Theory Report

This report demonstrates the implementation of advanced Security Operations Center (SOC) practices, including log analysis, threat intelligence integration, incident escalation, alert triage, and evidence preservation.

The project simulates real-world cyber attack scenarios using tools such as Wazuh, Metasploit, AlienVault OTX, and TheHive. Logs are analyzed and correlated to detect suspicious activities, while threat intelligence is used to validate indicators of compromise.

A complete SOC workflow is implemented, covering detection, investigation, response, escalation, and reporting. The project also includes evidence collection and forensic analysis to maintain data integrity.

METHODOLOGY USED
1. Advanced Log Analysis Methodology
The methodology for advanced log analysis focuses on identifying security incidents by correlating logs from multiple sources and detecting anomalies.

Steps Followed:
1.Collected logs from endpoints, network traffic, and authentication systems.
2.Identified suspicious patterns such as repeated failed logins (Event ID 4625).
3.Correlated authentication logs with outbound network activity.
4.Applied anomaly detection rules (e.g., high data transfer).
5.Enriched logs using contextual data such as IP geolocation.

Outcome:
This methodology helps in detecting brute-force attacks, lateral movement, and abnormal behavior while reducing false positives.

2. Threat Intelligence Integration Methodology
This methodology integrates external threat intelligence into SOC operations to improve detection accuracy.

Steps Followed:
1.Imported threat intelligence feeds from AlienVault OTX.
2.Extracted Indicators of Compromise (IOCs) such as IPs and hashes.
3.Matched IOCs against alerts generated in Wazuh.
4.Enriched alerts with reputation data.
5.Used MITRE ATT&CK techniques for threat mapping.

Outcome:
Improved alert validation and faster identification of malicious activity using real-time intelligence.

3.Incident Escalation Methodology
The escalation methodology ensures that security incidents are handled efficiently based on severity and complexity.

Steps Followed:
1.Classified alerts based on severity (Low, Medium, High).
2.Performed initial triage (Tier 1).
3.Escalated high-priority incidents to Tier 2 analysts.
4.Documented incidents using structured SITREP format.
5.Applied automated workflows using SOAR tools.

Outcome:
Ensures timely response, proper communication, and efficient incident handling.

4. Alert Triage Methodology
Alert triage methodology is used to analyze and prioritize security alerts.

Steps Followed:
1.Reviewed alerts generated by Wazuh.
2.Identified critical alerts such as PowerShell execution.
3.Validated IOCs using VirusTotal and OTX.
4.Assigned priority levels based on severity.
5.Updated alert status (Open, Investigating, Closed).

Outcome:
Helps reduce alert fatigue and ensures focus on critical threats.

5. Evidence Preservation Methodology
This methodology ensures that digital evidence is collected and preserved without tampering.

Steps Followed:
1.Collected volatile data (network connections, memory).
2.Acquired system memory using Velociraptor.
3.Generated SHA256 hash for integrity verification.
4.Documented chain-of-custody details.
5.Stored evidence securely.

Outcome:
Maintains integrity and admissibility of evidence for forensic analysis.

6. Capstone Project Methodology (Full SOC Workflow)
This methodology simulates a complete SOC workflow from attack detection to response and reporting.

Steps Followed:
1.Simulated attack using Metasploit (Samba exploit).
2.Detected attack using Wazuh alerts.
3.Performed alert triage and validation.
4.Responded by isolating system and blocking attacker IP.
5.Escalated incident using TheHive.
6.Documented full incident report and timeline.

Outcome:
Provides hands-on experience in real-world SOC operations including detection, response, and reporting.
